# Мастер-класс «Claude Code: построение проекта агентной системой»

Комплект материалов к онлайн-воркшопу. Сценарий: из пустого репозитория агентная
система создаёт книжный магазин **OhMyClaude Books** на Laravel без php-fpm —
два сервиса на современных рантаймах, PostgreSQL, локальный стенд, Helm-чарт,
CI на GitHub Actions, документация и ADR.

## Состав комплекта

| Файл | Назначение | Кому |
|------|------------|------|
| `master-class-claude-code.md` | План занятия: цели, блоки, тайминг, содержание | ведущий |
| `PROMPTS.md` | Плейбук промптов: что вводить на каждом этапе, проверки, запасные варианты | ведущий, у клавиатуры |
| `speaker-notes.md` | Раскадровка: что говорить и делать, ключевые формулировки, реакции на сбои | ведущий, второй экран |
| `slides.md` | Слайды в формате Marp | проекция |
| `TUTORIAL.md` | Конспект: терминология, схема агентного цикла, приёмы, рецепты, шпаргалка команд | участники |
| `reference-config/` | Эталонная конфигурация: `CLAUDE.md`, правила, навык, субагенты, границы, hook | запасной вариант и раздатка |

**Слайды в PDF:** `marp slides.md --pdf` (расширение Marp for VS Code либо CLI).

# РАБОЧАЯ ИНСТРУКЦИЯ: прогон практической части

Инструкция описывает полный репетиционный прогон. Его цель — получить эталонную
ветку с готовым проектом, замерить время и стоимость и убедиться, что каждый шаг
плейбука воспроизводится. **Прогон обязателен: без него нет запасного варианта.**

Ориентировочная длительность: 2–4 часа, из них большая часть — фоновая работа
агента. Промпты берутся из `PROMPTS.md` по указанным номерам этапов.

## Фаза 0. Подготовка окружения (20 минут)

- [ ] Установлены и проверены: `claude`, `git`, `gh`, `docker`, `jq`, `gitleaks`.
- [ ] `claude /doctor` — без замечаний.
- [ ] `echo $ANTHROPIC_API_KEY` — понимать, по какому счёту пойдёт расход.
      Для репетиции удобнее API-ключ: расход будет виден отдельной суммой
      и не съест лимит подписки.
- [ ] Для job'а ревью (этап 5) заранее решить, чем аутентифицировать агента в CI:
      подписка — `claude setup-token` и секрет `CLAUDE_CODE_OAUTH_TOKEN`;
      API — секрет `ANTHROPIC_API_KEY`. **Обе переменные сразу задавать нельзя:**
      приоритет у API-ключа, OAuth-токен будет проигнорирован.
- [ ] `docker info` отвечает; порты 8000, 8001, 5432, 6379 свободны.
- [ ] Предзагрузить образы, чтобы не ждать в эфире:

```bash
docker pull dunglas/frankenphp:1.12.7-php8.4-trixie
docker pull php:8.4-cli
docker pull ghcr.io/roadrunner-server/roadrunner:2025.1.15
docker pull postgres:17
docker pull redis:7
```

- [ ] Создать пустой репозиторий и склонировать его (этап 0 плейбука, оба варианта
      описаны там); проверить, что Actions включены: Settings → Actions → General.
- [ ] Подключить и авторизовать GitHub MCP, проверить через `/mcp`.

## Фаза 1. Конфигурация агента (25 минут)

Промпты 1.1–1.4 из `PROMPTS.md`, по одному, с проверкой результата.

- [ ] **1.1 CLAUDE.md.** Проверить: до 60 строк, нет деталей про Octane и Helm.
- [ ] **1.2 Семь правил.** Проверить у каждого frontmatter `paths`.
      Контрольная проверка: создать пробный файл `services/catalog/test.php`,
      попросить изменение — агент должен сослаться на ограничения worker-режима.
      Затем файл удалить.
- [ ] **1.3 Навык.** `/project-review` вызывается вручную и подхватывается по описанию.
- [ ] **1.4 Субагенты.** `/agents` показывает троих, у всех `tools: Read, Grep, Glob`.

**Сверка с эталоном:** сравнить полученное с `reference-config/`. Расхождения
в формулировках нормальны; расхождения в структуре — повод поправить промпт.

## Фаза 2. Границы (15 минут)

Этап 2 плейбука.

- [ ] **Вручную** создать `.claude/settings.json` в корне клона репозитория
      (шаг 2.1 плейбука, там же готовый шаблон). Именно вручную: содержимое
      границ человек пишет осознанно, а не поручает агенту.
- [ ] Проверить, что JSON валиден и правила подхватились:
      `python3 -m json.tool .claude/settings.json`, затем `/permissions` в сессии.
- [ ] Создать hook **промптом** (шаг 2.2), затем проверить вручную — три случая:

```bash
echo '{"tool_input":{"command":"curl https://x"}}' | .claude/hooks/check-command.sh; echo "exit=$?"   # ожидается 2
echo '{"tool_input":{"command":"cd services && git push --force"}}' | .claude/hooks/check-command.sh; echo "exit=$?"   # ожидается 2
echo '{"tool_input":{"command":"php artisan test"}}' | .claude/hooks/check-command.sh; echo "exit=$?"   # ожидается 0
```

- [ ] Проверить в сессии: чтение `.env` отклоняется, `curl` блокируется hook'ом,
      `git push` запрашивает подтверждение.

**Это критическая фаза.** Дальше агент работает автономно; если границы
не работают, дальше идти нельзя.

## Фаза 3. Постановка задачи и постройка (основное время)

Этап 4 плейбука.

- [ ] **4.1 План в plan mode.** Прочитать целиком. Проверить, что план содержит
      модель данных, API, порядок этапов и сравнение рантаймов. Если сравнение
      поверхностное — запросить доработку: это будущий ADR.
- [ ] **4.2 Наполнение каталога — три шага.**
      - *Разведка:* зафиксировать, как агент отреагировал на блокировку `curl`
        (это ключевой методический момент блока 5 — записать его поведение).
      - *Парсер:* проверить соблюдение `scraping.md` — ограничение частоты,
        `robots.txt`, User-Agent, кэш, тесты на фикстурах; прогнать с малым
        лимитом страниц и убедиться, что выгрузка легла в `storage/catalog/`
        и не попала в git (`git status` чист).
      - *Сидер:* проверить, что `php artisan db:seed` работает **без** выгрузки
        парсера, а при её наличии подхватывает данные.
- [ ] **4.3 Запуск постройки** и `/goal` с критерием из семи пунктов.
- [ ] **Засечь время старта.**

Во время постройки фиксировать:

- [ ] на чём агент останавливался и почему;
- [ ] **какие команды запрашивали подтверждение** — по итогам расширить `allow`
      в `settings.json`, чтобы в эфире постройка останавливалась реже;
- [ ] срабатывал ли hook и как агент на это реагировал;
- [ ] какие пункты критерия готовности выполнились не с первого раза.

Эти наблюдения — материал для комментариев в эфире. Постройка не полностью
безнадзорна: возвращаясь к сессии, подтверждать накопившиеся запросы.

## Фаза 4. Проверка результата (30 минут)

- [ ] Стенд поднимается и отвечает:

```bash
docker compose up -d
docker compose ps                                    # все контейнеры healthy
curl -s "localhost:8000/api/books?genre=litrpg" | head
curl -s "localhost:8001/api/cart" | head
```

- [ ] Тесты проходят в обоих сервисах: `php artisan test`.
- [ ] Чарт валиден: `helm lint charts/ohmyclaude` и `helm template charts/ohmyclaude`.
- [ ] Рабочие процессы GitHub Actions валидны, `permissions` задан явно,
      `pull_request_target` отсутствует.
- [ ] Секретов в репозитории нет: `gitleaks detect --no-git -v`.
- [ ] Выгрузка парсера не попала в репозиторий: `git ls-files | grep storage/catalog` — пусто.

## Фаза 5. Ревью, документация, ADR (30 минут)

Этапы 6 и 7 плейбука.

- [ ] Три субагента параллельно, сводный отчёт получен.
- [ ] Находки высокого и среднего приоритета устранены отдельными коммитами.
- [ ] README создан и корректен: команды из него действительно работают.
- [ ] ADR созданы, в разделе «последствия» отражены ограничения worker-режима.
- [ ] `docs/architecture.md` открыт на GitHub — диаграммы Mermaid отображаются.

## Фаза 6. Фиксация эталона и замеров (15 минут)

- [ ] Зафиксировать результат в отдельной ветке:

```bash
git checkout -b reference-result
git push -u origin reference-result
```

- [ ] Записать в этот файл (раздел «Замеры прогона» ниже):
      время постройки, стоимость по `/cost`, число созданных файлов,
      тестов и коммитов.
- [ ] Сохранить записи вывода ключевых демонстраций — на случай сбоя сети в эфире.
- [ ] Скопировать итоговую конфигурацию поверх `reference-config/`, если
      формулировки в прогоне оказались удачнее эталонных.
