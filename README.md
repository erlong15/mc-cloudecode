# Мастер-класс «Claude Code: построение проекта агентной системой»

Комплект материалов к онлайн-воркшопу. Сценарий: из пустого репозитория агентная
система создаёт книжный магазин **OhMyClaude Books** на Laravel без php-fpm —
подробности в `master-class-claude-code.md`.

## Состав комплекта

| Файл | Назначение | Кому |
|------|------------|------|
| `master-class-claude-code.md` | Программа: аудитория, результаты, тайминг, суть блоков | ведущий, анонс |
| `PROMPTS.md` | Плейбук: промпты, команды, объяснения шагов, запасные варианты | ведущий, у клавиатуры |
| `speaker-notes.md` | Раскадровка: что говорить и делать, реакции на сбои, предполётный чек-лист | ведущий, второй экран |
| `slides.md` | Слайды в формате Marp (`marp slides.md --pdf`) | проекция |
| `TUTORIAL.md` | Конспект: терминология, механики, приёмы, рецепты, шпаргалка команд | участники |
| `reference-config/` | Эталонная конфигурация | запасной вариант и раздатка |

# РАБОЧАЯ ИНСТРУКЦИЯ: репетиционный прогон

Цель прогона: получить эталонную ветку с готовым проектом, замерить время
и стоимость, убедиться, что каждый шаг плейбука воспроизводится.
**Прогон обязателен: без него нет запасного варианта эфира.**

Длительность: 2–4 часа, большая часть — фоновая работа агента.
Порядок и команды — в `PROMPTS.md`; здесь — **критерии приёмки** каждой фазы.

## Фаза 0. Окружение (этапы 0 и 3 плейбука)

- [ ] Установлены: `claude`, `git`, `gh`, `docker`, `jq`, `gitleaks`; `/doctor` без замечаний.
- [ ] Понятно, по какому счёту пойдёт расход (`echo $ANTHROPIC_API_KEY`);
      для репетиции удобнее API-ключ — расход виден отдельной суммой.
- [ ] Выбран способ аутентификации агента в CI — подписка или API
      (этап 0 плейбука, там же ловушка одновременных переменных).
- [ ] Порты 8000, 8001, 5432, 6379 свободны; образы предзагружены:

```bash
for img in dunglas/frankenphp:1.12.7-php8.4-trixie php:8.4-cli postgres:17 \
           redis:7 ghcr.io/roadrunner-server/roadrunner:2025.1.15; do
  docker pull "$img"
done
```

- [ ] Репозиторий создан, склонирован, ветка `main` существует, Actions включены
      (этап 0).
- [ ] GitHub MCP подключён токеном в заголовке (этап 3): `/mcp` — статус зелёный.

## Фаза 1. Конфигурация (этап 1, промпты 1.1–1.4)

- [ ] `CLAUDE.md` — до 60 строк, без деталей про Octane и Helm.
- [ ] Семь правил с frontmatter `paths`. Контроль: пробный файл
      `services/catalog/test.php` → запрос изменения → агент ссылается
      на ограничения worker-режима (файл затем удалить).
- [ ] `/project-review` вызывается вручную и подхватывается по описанию.
- [ ] `/agents` показывает **троих** ревьюеров, у всех `tools: Read, Grep, Glob`.
      Исполнитель здесь не создаётся — его очередь на шаге 2b этапа 4.
- [ ] Результат сопоставлен с `reference-config/`: расхождения в формулировках
      допустимы, в структуре — повод поправить промпт.

## Фаза 2. Границы (этап 2)

- [ ] `.claude/settings.json` создан **вручную** (шаг 2.1), JSON валиден,
      `/permissions` показывает правила.
- [ ] Hook создан промптом (шаг 2.2) и проходит три проверки оттуда же:
      простая команда — блок, составная — блок, разрешённая — проходит.
- [ ] В сессии: чтение `.env` отклонено; `curl` заблокирован hook'ом;
      `git push` требует подтверждения.

**Критическая фаза:** дальше агент работает автономно. Границы не работают —
дальше не идти.

## Фаза 3. Постановка и постройка (этап 4)

- [ ] **4.1:** план содержит модель данных, API, порядок этапов и содержательное
      сравнение рантаймов (это будущий ADR).
- [ ] **4.1b:** план сохранён в `docs/plan.md` и закоммичен.
- [ ] **4.2 шаг 1:** агент вышел в сеть через `WebFetch` (зафиксировать для
      блока 5); выводы в `docs/research/catalog-source.md` — свои заметки,
      не текст чужих страниц.
- [ ] **4.2 шаг 2:** парсер соблюдает `scraping.md`; пробный запуск с малым
      лимитом → выгрузка в `storage/catalog/`, `git status` чист.
- [ ] **4.2 шаг 2b:** `/context` показан; `implementer` создан, в `/agents`
      четвёртый агент с `Edit`, `Write`, `Bash`.
- [ ] **4.2 шаг 3:** сидер сделан **исполнителем**; в сводке — хеш коммита;
      `php artisan db:seed` работает без выгрузки парсера, с ней — подхватывает.
- [ ] **4.3:** выполняется **после** сводки исполнителя и проверки сидера —
      граница «управляли каждым шагом → агент работает сам» должна быть чистой.
      Порядок этапов и критерий готовности записаны в `docs/plan.md`;
      постройка запущена одной командой `/goal`. **Время старта засечено.**

Во время постройки фиксировать (материал для эфира и правок конфигурации):

- [ ] на чём агент останавливался и почему;
- [ ] какие команды запрашивали подтверждение → расширить `allow`;
- [ ] срабатывания hook и реакция агента;
- [ ] пункты критерия, не выполнившиеся с первого раза.

## Фаза 4. Проверка результата

- [ ] Стенд: `docker compose up -d` → все контейнеры healthy;
      каталог отвечает (`localhost:8000/api/books?genre=litrpg`),
      заказы отвечают (`localhost:8001/api/cart`).
- [ ] `php artisan test` проходит в обоих сервисах.
- [ ] `helm lint` и `helm template` для `charts/ohmyclaude` без ошибок.
- [ ] Workflows: `permissions` задан явно, `pull_request_target` отсутствует.
- [ ] `gitleaks detect --no-git -v` — секретов нет.
- [ ] `git ls-files | grep storage/catalog` — пусто.

## Фаза 5. Ревью, документация, ADR (этапы 6 и 7)
