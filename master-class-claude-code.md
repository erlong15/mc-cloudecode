# Программа: Claude Code — построение проекта агентной системой

Обзорный документ занятия: для кого, что получат, из чего состоит и в каком
порядке. Подробности намеренно не здесь — у каждого знания один документ-владелец:

| Вопрос | Документ |
|--------|----------|
| Что вводить на каждом этапе, проверки, запасные варианты | `PROMPTS.md` |
| Что говорить и делать, реакции на сбои, тайм-чеки | `speaker-notes.md` |
| Термины, механики (plan mode, /goal, границы, инъекция), рецепты | `TUTORIAL.md` |
| Подготовка и репетиционный прогон | `README.md` |
| Эталонная конфигурация | `reference-config/` |

---

## Формат и аудитория

**Формат:** онлайн-воркшоп, 142 минуты (2:22); ведущий показывает —
участники повторяют. Занятие для своих: тайминг — ориентир, приоритет
у практики, выход за два часа допустим.

**Аудитория:** DevOps-инженеры, DBA, разработчики, техлиды. Участники уже
пробовали Claude Code для отдельных задач, но не выстраивали систему
его расширений.

**Что нужно участнику заранее:** установленный Claude Code, подписка
Pro/Max/Team Premium или ключ API, аккаунт GitHub, Docker, терминал.

## Сквозной сценарий

Из **пустого репозитория** агентная система создаёт работающий бэкенд-проект,
а участники по ходу настраивают её узлы. Предметная область — книжный магазин
**OhMyClaude Books** на Laravel **без php-fpm**: два сервиса на рантаймах
с постоянными воркерами (FrankenPHP и RoadRunner), PostgreSQL, локальный стенд
на docker-compose, Helm-чарт, CI на GitHub Actions, документация и ADR.
Каталог наполняется парсером публичной площадки (выгрузка вне репозитория)
и синтетическим скриптом наполнения.

Постройка запускается в середине занятия командой `/goal` и работает в фоне,
пока разбираются субагенты, автономные режимы и стоимость; финал — живой стенд,
история коммитов и зелёный конвейер.

Материал построен вокруг двух понятий: **контекст** (что агент знает)
и **границы** (что ему можно), с рефреном «просьба живёт в модели, правило —
в harness».

## Что получит участник

1. Понимание устройства агента (модель + harness) и карту возможностей
   с принципом выбора.
2. Отработанный руками навык: память проекта, правило, навык, субагент,
   границы через permissions и hooks.
3. Метод постановки задачи, при котором агент строит проект целиком:
   план до кода → сохранение артефактов в репозиторий → проверяемый критерий →
   автономное доведение.
4. Рецепт встраивания в pipeline: headless-режим и job ревью на GitHub Actions,
   включая аутентификацию по подписке.
5. Понимание модели стоимости — с реальной цифрой постройки, замеренной
   на репетиции.
6. Раздатку: `TUTORIAL.md` и эталонную конфигурацию `reference-config/`.

**По ролям:** разработчик — метод постановки и доведение до зелёных тестов;
DBA — правила миграций и ревью схемы субагентом; DevOps — guardrails as code
и агент в CI; техлид — иерархия настроек, тиражирование конфигурации, контроль
стоимости.

Два структурных правила, на которых держится порядок: **границы настраиваются
до запуска постройки** (блок 3 раньше блока 5) и **пока объясняем — работает
основная сессия на виду, ушли в фон — делегируем**.

## Подготовка

Репетиционный прогон по инструкции в `README.md` обязателен: он создаёт
эталонную ветку (запасной вариант эфира и раздатку) и даёт замеры времени
и стоимости для блока 8. Перед проведением сверить изменяемые сведения —
их список с датой последней проверки ведётся в `README.md`, раздел
«Что требует сверки в день проведения».
