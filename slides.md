# Блок 1
## Агент = модель + harness

---

# Что умеет модель

Ровно одно: **читать текст → порождать текст**

в том числе: «вызови инструмент Read с таким-то путём»

- не запускает команды
- не читает файлы
- ничего не помнит между запросами — **stateless**

Каждый запрос — полный пакет всего, что ей нужно знать.
Кто-то должен этот пакет собрать.

---

# Что делает harness

**Harness** — обвязка вокруг модели. Claude Code — это и есть harness.

| Harness | |
|---|---|
| собирает | каждый запрос к модели |
| ведёт | цикл: инструмент → результат → снова модель |
| исполняет | инструменты: Read, Write, Bash, Grep… |
| проверяет | права на каждое действие |
| управляет | окном контекста |

## Агент = модель + harness

---

# Что уходит в каждый запрос

Окно контекста ≈ **200 000 токенов** — и в нём всё:

1. Системный промпт Claude Code
2. **CLAUDE.md** + правила, подгруженные под текущие файлы
3. Описания инструментов, навыков, имена MCP-инструментов
4. Вся история диалога — включая результаты инструментов

Всё, что мы настроим, **конкурирует за это окно**
→ экономия контекста — сквозная тема занятия

---

# Агентный цикл

```
задача
  → модель выбирает инструмент
      → PreToolUse hook              ← блок 3
      → permissions: deny/ask/allow  ← блок 3
      → выполнение
      → PostToolUse hook             ← блок 3
  → результат в контекст
  → снова модель → … → ответ
```

CLAUDE.md и правила — в запросе · навыки и MCP — новые инструменты
субагент — такой же цикл со своим окном

---

# Вывод блока 1

> **Просьбы живут в модели** — она старается, но может забыть.
> **Правила живут в harness** — они срабатывают всегда.

Расширяют модель — *что она знает и умеет*:
CLAUDE.md, правила, навыки, MCP, субагенты

Настраивают harness — *что ей можно*:
permissions, hooks

# Карта: ситуация → возможность

| Ситуация | Что применить |
|----------|---------------|
| Агент дважды ошибается в соглашении | **CLAUDE.md** |

# Блок 2
## Пустой репозиторий → память и правила

---

# CLAUDE.md — ядро памяти

- Загружается **в каждый запрос**
- Создаётся командой **`/init`**, в пустом репозитории — пишется под задачу
- Объём — **до 200 строк**: тематика → в правила, справка → в навыки
- Пишем **на английском** — это инструкция для модели

**Что внутри:** карта репозитория · универсальные соглашения ·
ограничения · порядок ревью

**Чего внутри нет:** деталей по областям — для них правила

---

# .claude/rules/ — правила по путям

```markdown
---
paths:
  - "services/**/*.php"
  - "services/**/Dockerfile"
---
# Laravel Octane worker mode
- Never inject the container or Request into a singleton constructor
- No static properties accumulating state between requests
- Octane::concurrently() and ticks are Swoole-only — do not use
```

Подгружается **только** при работе с совпавшими файлами

Семь правил: laravel · octane · containers · database · helm · github-actions · scraping

---

# CLAUDE.md и правила: нюансы

- **Больше 200 строк — инструкции теряются.** Ядро в CLAUDE.md,
  темы — в правилах, справка — в навыках
- Правило **без `paths`** действует всегда; **с `paths`** — только на совпавших
- `~/.claude/rules/` — личные правила для всех ваших проектов
- Агент «не видит» правило? → файл не попадает под glob-паттерн
- Не описывайте то, что видно из кода, — только неочевидное

---

# Навыки и субагенты — создаёт сам агент

**Приём:** конфигурацию агента пишет агент. По одному промпту на артефакт.
Человек проверяет и правит.

| Артефакт | Назначение |
|----------|-----------|
| навык `project-review` | чеклист проверки по всем слоям |
| `code-reviewer` | код Laravel + корректность worker-режима |
| `security-auditor` | контейнеры, чарт, GitHub Actions |
| `db-reviewer` | схема и миграции |

Все ревьюеры — **только чтение**: `tools: Read, Grep, Glob`

# Иерархия настроек

| Уровень | Кто задаёт |
|---------|-----------|
| `managed-settings.json` | организация — **не переопределить** |
| `--settings` (CLI) | сценарии и CI |
| `.claude/settings.local.json` | разработчик лично |
| `.claude/settings.json` | **команда — в репозитории** |
| `~/.claude/settings.json` | разработчик, все проекты |

Стандарт команды приезжает с `git clone`

---

# permissions: deny → ask → allow

```json
{
  "permissions": {
    "deny":  ["Read(**/.env)", "Read(**/*.key)", "Bash(sudo:*)"],
    "ask":   ["Bash(git push:*)", "Bash(docker compose down:*)"],
    "allow": ["Bash(php artisan:*)", "Bash(./vendor/bin/pest:*)",
              "Bash(docker compose up:*)", "Bash(helm lint:*)"]
  }
}
```

Первое совпавшее правило выигрывает · применяется без перезапуска

**Важный нюанс:** сопоставление **префиксное** —
`Bash(git push:*)` не поймает `cd services && git push`

---

# Hooks: события и каналы

| Событие | Применение |
|---------|-----------|
| `PreToolUse` | блокировка команд, валидация |
| `PostToolUse` | линтер, автоформат, поиск секретов |
| `UserPromptSubmit` | добавить контекст / заблокировать промпт |
| `SessionStart` | подгрузить окружение |
| `Stop` | проверка полноты работы |

**stdin** → JSON (`tool_name`, `tool_input`) · `matcher` — regex
**exit 0** → разрешено · **exit 2** → блок, stderr уходит модели
Отладка: `claude --debug` · hook — код: ревью и репозиторий

---

# Hook закрывает то, что не закрывают permissions

```bash
cmd=$(printf '%s' "$input" | jq -r '.tool_input.command // ""')

for pattern in "${blocked[@]}"; do
  if [[ "$cmd" == *"$pattern"* ]]; then
    echo "Blocked: forbidden pattern '${pattern}'" >&2
    exit 2
  fi
done
```

Проверяется **вся строка команды** — включая то, что после `&&` и `|`

**guardrails as code:** правила лежат в репозитории рядом с кодом

# Блок 5
## Постановка задачи и запуск постройки

---

# Метод: четыре элемента постановки

1. **План до кода** — plan mode: агент проектирует, ничего не записывая.
   План читает и утверждает человек
2. **Проверяемый критерий готовности** — не «сделай магазин», а список условий
3. **Порядок работ** — этапы с точками коммитов
4. **Автономное доведение** — `/goal` до выполнения критерия

Источник паттернов: **официальная библиотека промптов**
code.claude.com/docs/en/prompt-library — 50+ промптов, Discover → Operate
*Ценность — в переносимых паттернах, а не в формулировках*

---

# Наполнение каталога: два слоя

**Парсер** — инструмент проекта: разбирается со структурой стороннего каталога,
собирает публичные метаданные в `storage/catalog/`

**Базовый сидер** — синтетические данные, коммитятся в репозиторий

> Парсер живёт в репозитории. Его **выгрузка** — нет.
> Проект должен запускаться у любого, кто его склонировал.

Дисциплина запросов — в правиле `scraping.md`:
`robots.txt` · не чаще 1 запроса в секунду · backoff · User-Agent · кэш

---

# Момент истины: guardrail срабатывает

Агент идёт на разведку структуры → пробует `curl` → **заблокирован**
нашим же `deny` и hook'ом из блока 3

> Это не поломка демонстрации. Это то, за что мы платим, ставя границы.

**Правильная реакция — не отключить правило, а принять решение:**
запросы во внешнюю сеть делает **код приложения** — с ограничением частоты,
User-Agent и обработкой ошибок, — а не shell-команда в обход всего

Guardrail не помешал работе. Он подтолкнул к правильному решению.

# Критерий готовности

```
1. docker compose up поднимает стенд, контейнеры healthy
2. каталог отвечает: список, карточка, поиск, фильтр по жанру
3. заказы отвечают: корзина, оформление
4. php artisan test проходит в обоих сервисах
5. линтер чист
6. helm lint и helm template без ошибок
7. рабочий процесс GitHub Actions валиден
```

```
/goal все семь пунктов критерия готовности выполняются
```

`/goal` — самая явная форма этого паттерна.

# Блок 6
## Субагенты

---

# Формы агентности

1. **Встроенные** — Explore, Plan (read-only «из коробки»), general-purpose
2. **Кастомные** — `.claude/agents/*.md`: инструкция, инструменты, модель
3. **Фоновые** — работают, пока вы заняты другим
4. **Параллельные сессии** — git worktrees: свой каталог и ветка на задачу
5. **Облачные** — по расписанию, машина не нужна
6. **Agent Teams** — экспериментально, дорого по токенам

---

# Субагент = изоляция контекста

Читает **50 файлов** → в вашу сессию возвращается **сводка**

```markdown
---
name: db-reviewer
description: Read-only review of schema, migrations and seeders.
tools: Read, Grep, Glob      ← только чтение
model: sonnet
---
You are an experienced DBA...
```

**Правило безопасности:** ревьюеры — только чтение.
Право записи — у основного агента, который спрашивает вас.

---

# Субагенты: нюансы

- **Не для мелочей** — запуск дороже инлайн-ответа
- Вернётся только сводка → в инструкции задайте **формат отчёта**
- Субагент **не видит вашу переписку** — контекст задаётся
  его описанием и промптом запуска
- Узкий специалист точнее универсала
- Модель — в frontmatter: sonnet ревьюерам, haiku механике

# Четыре способа снять ручное управление

| Механизм | Принцип | Применение |
|----------|---------|-----------|
| **/goal** | до условия | доведение постройки до критерия |
| **/loop** | по времени | периодические тесты и аудит |
| **/schedule** | облако, cron | регулярный аудит без сессии |
| **claude -p** | headless | ревью в GitHub Actions |

**Разграничение:** hook — по событию · `/loop` — по времени ·
`/goal` — до условия · `/schedule` — по расписанию

---

# Claude Code в GitHub Actions

```yaml
permissions:
  contents: read
  pull-requests: write

steps:
  - run: npm install -g @anthropic-ai/claude-code
  - run: claude -p "Проверь изменения по чеклисту project-review"
        --allowedTools "Read,Grep,Glob" --output-format json
    env:
      ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

Ключ — из секретов · права агента — **только чтение** ·
`permissions` — явно и по минимуму · никакого `pull_request_target`

# Блок 10
## ADR и архитектурная схема

---

# ADR: решение, а не декларация

Формат: **контекст → варианты → решение → последствия**

1. Отказ от php-fpm в пользу Octane: что даёт, чем оплачивается
2. FrankenPHP для каталога, RoadRunner для заказов — сравнение моделей
3. Разделение на два сервиса и способ взаимодействия
4. PostgreSQL и стратегия миграций

**Раздел «последствия» — честно:** ограничения worker-режима,
риск утечек памяти, `octane:reload` после деплоя

---

# Два рантайма — предмет сравнения

| | FrankenPHP | RoadRunner |
|---|---|---|
| Модель | PHP внутри сервера (Caddy) | Go-сервер + пул PHP-воркеров |
| IPC | нет | goridge |
| Из коробки | TLS, HTTP/2, HTTP/3, статика | плагины: Jobs, gRPC, KV |
| Ближе к | «всё в одном контейнере» | классике за обратным прокси |

Общее: приложение живёт между запросами → дисциплина в работе с состоянием

*Разные рантаймы в одном проекте — учебное решение ради сравнения*

---

# Схема — на Mermaid

GitHub рендерит нативно, отдельные инструменты не нужны

- схема компонентов стенда: сервисы, PostgreSQL, Redis, потоки запросов
- схема развёртывания в Kubernetes: образы, ingress, secrets, пробы

Документация и архитектурные решения — **часть результата**,
а не приложение к нему
