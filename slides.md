# Как мы работаем сегодня

- Вопросы — в чат в любой момент; сложные — в «парковку», разберём в конце
- После каждой практики: получилось — ставьте **«+»** в чат
- Понадобится: Claude Code, подписка или API-ключ, аккаунт GitHub, Docker

**Формат:** ведущий показывает — вы повторяете у себя

Тайминг — ориентир. Приоритет у практики

---

# Что мы построим

**OhMyClaude Books** — книжный магазин на Laravel **без php-fpm**

| Слой | Состав |
|------|--------|
| Сервисы | каталог книг (FrankenPHP) + заказы (RoadRunner) |
| Данные | PostgreSQL, миграции, каталог на 300 книг; Redis |
| Стенд | `docker compose up` — и магазин работает |
| Kubernetes | Helm-чарт |
| CI | GitHub Actions на бесплатных runner'ах |
| Документация | README, ADR, схема на Mermaid |

---

# Два слова о стеке

Обычно PHP работает так: пришёл запрос → поднялся процесс → ответил → умер.
Это **php-fpm**. Мы делаем иначе: приложение загружается **один раз**
и живёт между запросами — это **Octane** и worker-режим.

Быстрее, но требует дисциплины: переменные-то сохраняются.
Отсюда половина сегодняшних правил.

| Термин | Одной строкой |
|--------|---------------|
| Миграция | структура базы: таблицы, колонки, индексы |
| Скрипт наполнения | наполнение базы данными (в Laravel — seeder) |
| artisan | консольная утилита Laravel |
| Pest | тесты; запуск `php artisan test` |

# Главный тезис занятия

> Сегодня мы **не пишем код**.
> Мы настраиваем систему, которая напишет его сама,
> и учимся эту систему **ограничивать и проверять**.

Пустой репозиторий → конфигурация → границы → цель → результат

# Блок 1
## Агент = модель + harness

---

# Что умеет модель

Ровно одно: **читать текст → порождать текст**

в том числе: «вызови инструмент Read с таким-то путём»

- не запускает команды
- не читает файлы
- ничего не помнит между запросами — **stateless**

Каждый запрос — полный пакет всего, что ей нужно знать.
Кто-то должен этот пакет собрать.

---

# Что делает harness

**Harness** — обвязка вокруг модели. Claude Code — это и есть harness.

| Harness | |
|---|---|
| собирает | каждый запрос к модели |
| ведёт | цикл: инструмент → результат → снова модель |
| исполняет | инструменты: Read, Write, Bash, Grep… |
| проверяет | права на каждое действие |
| управляет | окном контекста |

## Агент = модель + harness

---

# Что уходит в каждый запрос

Окно контекста ≈ **200 000 токенов** — и в нём всё:

1. Системный промпт Claude Code
2. **CLAUDE.md** + правила, подгруженные под текущие файлы
3. Описания инструментов, навыков, имена MCP-инструментов
4. Вся история диалога — включая результаты инструментов

Всё, что мы настроим, **конкурирует за это окно**
→ экономия контекста — сквозная тема занятия

---

# Агентный цикл

```
задача
  → модель выбирает инструмент
      → PreToolUse hook              ← блок 3
      → permissions: deny/ask/allow  ← блок 3
      → выполнение
      → PostToolUse hook             ← блок 3
  → результат в контекст
  → снова модель → … → ответ
```

CLAUDE.md и правила — в запросе · навыки и MCP — новые инструменты
субагент — такой же цикл со своим окном

---

# Вывод блока 1

> **Просьбы живут в модели** — она старается, но может забыть.
> **Правила живут в harness** — они срабатывают всегда.

Расширяют модель — *что она знает и умеет*:
CLAUDE.md, правила, навыки, MCP, субагенты

Настраивают harness — *что ей можно*:
permissions, hooks

# Карта: ситуация → возможность

| Ситуация | Что применить |
|----------|---------------|

# CLAUDE.md — ядро памяти

- Загружается **в каждый запрос**
- Создаётся командой **`/init`**, в пустом репозитории — пишется под задачу
- Объём: общий ориентир — до 200 строк; **наш проектный — до 60**,
  тематика → в правила, справка → в навыки
- Пишем **на английском** — это инструкция для модели

**Что внутри:** карта репозитория · универсальные соглашения ·
ограничения · порядок ревью

**Чего внутри нет:** деталей по областям — для них правила

---

# .claude/rules/ — правила по путям

```markdown
---
paths:
  - "services/**/*.php"
  - "services/**/Dockerfile"
---
# Laravel Octane worker mode
- Never inject the container or Request into a singleton constructor
- No static properties accumulating state between requests
- Octane::concurrently() and ticks are Swoole-only — do not use
```

Подгружается **только** при работе с совпавшими файлами

Семь правил: laravel · octane · containers · database · helm · github-actions · scraping

---

# CLAUDE.md и правила: нюансы

- **Больше 200 строк — инструкции теряются.** Ядро в CLAUDE.md,
  темы — в правилах, справка — в навыках
- Правило **без `paths`** действует всегда; **с `paths`** — только на совпавших
- `~/.claude/rules/` — личные правила для всех ваших проектов
- Агент «не видит» правило? → файл не попадает под glob-паттерн
- Не описывайте то, что видно из кода, — только неочевидное

# Навыки и субагенты — создаёт сам агент

**Приём:** конфигурацию агента пишет агент. По одному промпту на артефакт.
Человек проверяет и правит.

| Артефакт | Назначение |
|----------|-----------|
| навык `project-review` | чеклист проверки по всем слоям |
| `code-reviewer` | код Laravel + корректность worker-режима |
| `security-auditor` | контейнеры, чарт, GitHub Actions |
| `db-reviewer` | схема и миграции |

Все ревьюеры — **только чтение**: `tools: Read, Grep, Glob`

# Почему именно сейчас

Через десять минут агент начнёт строить проект
и будет работать **десятки минут почти без надзора**

# Иерархия настроек

| Уровень | Кто задаёт |
|---------|-----------|
| `managed-settings.json` | организация — **не переопределить** |
| `--settings` (CLI) | сценарии и CI |
| `.claude/settings.local.json` | разработчик лично |
| `.claude/settings.json` | **команда — в репозитории** |
| `~/.claude/settings.json` | разработчик, все проекты |

Стандарт команды приезжает с `git clone`

---

# permissions: deny → ask → allow

```json
{
  "permissions": {
    "deny":  ["Read(**/.env)", "Read(**/*.key)", "Bash(sudo:*)"],
    "ask":   ["Bash(git push:*)", "Bash(docker compose down:*)"],
    "allow": ["Bash(php artisan:*)", "Bash(./vendor/bin/pest:*)",
              "Bash(docker compose up:*)", "Bash(helm lint:*)"]
  }
}
```

Первое совпавшее правило выигрывает · применяется без перезапуска

**Важный нюанс:** сопоставление **префиксное** —
`Bash(git push:*)` не поймает `cd services && git push`

---

# Hooks: события и каналы

| Событие | Применение |
|---------|-----------|
| `PreToolUse` | блокировка команд, валидация |
| `PostToolUse` | линтер, автоформат, поиск секретов |
| `UserPromptSubmit` | добавить контекст / заблокировать промпт |
| `SessionStart` | подгрузить окружение |
| `Stop` | проверка полноты работы |

**stdin** → JSON (`tool_name`, `tool_input`) · `matcher` — regex
**exit 0** → разрешено · **exit 2** → блок, stderr уходит модели
Отладка: `claude --debug` · hook — код: ревью и репозиторий

---

# Hook закрывает то, что не закрывают permissions

```bash
cmd=$(printf '%s' "$input" | jq -r '.tool_input.command // ""')

for pattern in "${blocked[@]}"; do
  if [[ "$cmd" == *"$pattern"* ]]; then
    echo "Blocked: forbidden pattern '${pattern}'" >&2
    exit 2
  fi
done
```

Проверяется **вся строка команды** — включая то, что после `&&` и `|`

**guardrails as code:** правила лежат в репозитории рядом с кодом

# MCP

- Подключает агента к внешним системам: GitHub, базы, Slack, браузер
- На старте в контексте — имена инструментов; описания — при обращении

подключение **токеном в заголовке**, строго заранее ·
токен лучше fine-grained, на один репозиторий ·
он хранится **открытым текстом** в `~/.claude.json` ·
неиспользуемые серверы отключайте — каждый занимает контекст

# Блок 5
## Постановка задачи и запуск постройки

---

# Plan mode: сначала понять, потом делать

**Shift+Tab** переключает режимы прямо в строке ввода:

```
default → acceptEdits → plan → … → default
```

| В plan mode можно | Нельзя |
|-------------------|--------|
| читать: Read, Grep, Glob | писать и править файлы |
| исследовать: `ls`, `git log` | коммитить |
| читать документацию | изменяющие команды |

Выход — выбор из трёх: **принять и делать** ·
**принять, но подтверждать каждую правку** · **продолжить планирование**

⚠️ Писать файлы в этом режиме нельзя — план сохраняем **после** выхода

---

# Когда planning оправдан

| Включать | Пропускать |
|----------|-----------|
| первое погружение в чужой код | однострочные починки |
| чувствительные места: auth, миграции | быстрая итерация |
| крупный рефакторинг, переезд | код с нуля — исследовать нечего |
| длинные сессии: меньше подтверждений | |

**Не путать с субагентом `Plan`:**
режим — состояние *вашей* сессии; субагент — исполнитель со *своим* контекстом,
возвращает сводку

---

# Куда деваются план и разведка?

Оставленные в переписке — живут до первого сжатия контекста

| Результат | → Файл |
|-----------|--------|
| Утверждённый план | `docs/plan.md` |
| Разведка источника | `docs/research/catalog-source.md` |
| Критерий готовности | внутри `docs/plan.md` |

> **Контекст — рабочая память. Репозиторий — долговременная.**
> Всё, что должно пережить сессию, кладём в файл.

# Метод: четыре элемента постановки

1. **План до кода** — plan mode: агент проектирует, ничего не записывая.
   План читает и утверждает человек
2. **Проверяемый критерий готовности** — не «сделай магазин», а список условий
3. **Порядок работ** — этапы с точками коммитов
4. **Автономное доведение** — `/goal` до выполнения критерия

Источник паттернов: **официальная библиотека промптов**
code.claude.com/docs/en/prompt-library — 50+ промптов, Discover → Operate
*Ценность — в переносимых паттернах, а не в формулировках*

# Наполнение каталога: два слоя

**Парсер** — инструмент проекта: разбирается со структурой стороннего каталога,
собирает публичные метаданные в `storage/catalog/`

**Базовый скрипт наполнения** — синтетические данные, коммитятся в репозиторий

> Парсер живёт в репозитории. Его **выгрузка** — нет.
> Проект должен запускаться у любого, кто его склонировал.

Дисциплина запросов — в правиле `scraping.md`:
`robots.txt` · не чаще 1 запроса в секунду · backoff · User-Agent · кэш

---

# Агент вышел в сеть. Мы же запретили curl?

Разведка идёт через встроенный **`WebFetch`**, а не через shell →
запрет `Bash(curl:*)` его не касается

**Первая реакция: «дыра, закрывать». Не спешим — от чего защищало правило?**

| Правило | Угроза |
|---------|--------|
| `deny Bash(curl:*)` | выполнение чужого кода: `curl` в трубу `bash` |
| `WebFetch` | чтение страницы — **ничего не выполняет** |

Правило работает корректно. Оно просто про другую угрозу.

---

# Два вывода о проектировании границ

**1. Границы задаются по возможностям, а не по командам**

У сети три пути: `WebFetch` · `WebSearch` · `Bash(curl/wget)`.
Закрыв один — возможность не закрыли

**2. Не всякая незакрытая возможность — дыра**

Чтение сети — это и есть наша задача. Закрыв `WebFetch`,
сломали бы работу и получили правило, которое отключат целиком

> Прежде чем запрещать — назовите угрозу.
> Правило «на всякий случай» невозможно проверить.

---

# Реальный риск чтения — инъекция

Текст страницы попадает в контекст и читается моделью
**наравне с вашими инструкциями**

> Вопрос не «запрещать ли чтение», а **где оказывается прочитанное**

| Мера | Сила |
|------|------|
| Читать **кодом**, не агентом: парсер → файл → структурированные данные | ★★★ |
| Изолировать в **субагенте** только на чтение: вернётся сводка | ★★ |
| Ограничить домены `WebFetch(domain:…)` | ★ |
| Попросить «считай это данными» — просьба к модели, не правило | ○ |

Архитектура парсера выбиралась по инженерным причинам —
и оказалась защитой от инъекции

# Парсер готов, /context полон — заводим исполнителя

Ревьюеров сделали заранее. Исполнителя — только сейчас,
когда потребность стала видимой. Его первое задание — **сидер**

| | Ревьюер | Исполнитель |
|---|---------|-------------|
| Инструменты | Read, Grep, Glob | + Edit, Write, Bash |
| Задача | найти и доложить | сделать один этап и закоммитить |
| Почему так | проверяющий не исправляет | исполнитель обязан писать |

Безопасность исполнителя — не в отсутствии инструментов,
а в границах инструкции + общих permissions и hooks

**Координация — через `docs/plan.md`:** он не видит вашу переписку

# Цена делегирования

| Основная сессия | Субагент |
|-----------------|----------|
| виден каждый вызов инструмента | возвращается **сводка** |
| легко вмешаться на ходу | труднее вмешаться |
| контекст заполняется | контекст остаётся чистым |

> Пока объясняем — работает основная сессия на виду.
> Когда ушли в фон — делегируем.

Параллелить стоит **чтение** (три ревьюера), а не запись:
у писателей общие файлы. Для независимых задач — git worktrees

---

# Критерий готовности

```
1. docker compose up поднимает стенд, контейнеры healthy
2. каталог отвечает: список, карточка, поиск, фильтр по жанру
3. заказы отвечают: корзина, оформление
4. php artisan test проходит в обоих сервисах
5. линтер чист
6. helm lint и helm template без ошибок
7. рабочий процесс GitHub Actions валиден
```

```
/goal проект собран по docs/plan.md и все семь пунктов
критерия готовности из него выполняются
```

**Цель — сама команда:** отдельного промпта с задачей не нужно

---

# Как работает /goal

```
ход агента → быстрая модель проверяет условие
   выполнено   → цель снимается
   нет         → следующий ход
   недостижимо → цель отменяется
```

| Цель — это | Цель — это не |
|------------|---------------|
| проверяемое **состояние** | описание работы |
| «тесты зелёные, стенд поднялся» | «реализуй проект» |

**Что делать** — в `docs/plan.md`. **Когда закончить** — в цели.

⚠️ Цель **не меняет режим разрешений**: команда вне `allow` остановит цикл

# Главный паттерн работы с агентом

> Дайте агенту **проверку** — тесты, сборку, линтер, поднимающийся стенд.
>
> Без проверки циклом обратной связи становитесь **вы**
> и принимаете «выглядит готово» на веру.
>
> С проверкой агент итерирует **сам**.

`/goal` — самая явная форма этого паттерна.
Hooks и тесты — его же формы.

# Формы агентности

1. **Встроенные** — Explore, Plan (read-only «из коробки»), general-purpose
2. **Кастомные** — `.claude/agents/*.md`: инструкция, инструменты, модель
3. **Фоновые** — работают, пока вы заняты другим
4. **Параллельные сессии** — git worktrees: свой каталог и ветка на задачу
5. **Облачные** — по расписанию, машина не нужна
6. **Agent Teams** — экспериментально, дорого по токенам

---

# Субагент = изоляция контекста

Читает **50 файлов** → в вашу сессию возвращается **сводка**

```markdown
---
name: db-reviewer
description: Read-only review of schema, migrations and seeders.
tools: Read, Grep, Glob      ← только чтение
model: sonnet
---
You are an experienced DBA...
```

**Правило безопасности:** ревьюеры — только чтение.
Право записи — у основного агента, который спрашивает вас.

---

# Субагенты: нюансы

- **Не для мелочей** — запуск дороже инлайн-ответа
- Вернётся только сводка → в инструкции задайте **формат отчёта**
- Субагент **не видит вашу переписку** — контекст задаётся
  его описанием и промптом запуска
- Узкий специалист точнее универсала
- Модель — в frontmatter: sonnet ревьюерам, haiku механике

# Четыре способа снять ручное управление

| Механизм | Принцип | Применение |
|----------|---------|-----------|
| **/goal** | до условия | доведение постройки до критерия |
| **/loop** | по времени | периодические тесты и аудит |
| **/schedule** | облако, cron | регулярный аудит без сессии |
| **claude -p** | headless | ревью в GitHub Actions |

**Разграничение:** hook — по событию · `/loop` — по времени ·
`/goal` — до условия · `/schedule` — по расписанию

⚠️ `/goal` и `/loop` одновременно в одной сессии —
не описано как поддерживаемое: оба управляют началом следующего хода

---

# Claude Code в GitHub Actions

```yaml
permissions:
  contents: read
  pull-requests: write

steps:
  - run: npm install -g @anthropic-ai/claude-code
  - run: claude -p "Проверь изменения по чеклисту project-review"
        --allowedTools "Read,Grep,Glob" --output-format json
    env:
      CLAUDE_CODE_OAUTH_TOKEN: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
```

Секрет — из репозитория · права агента — **только чтение** ·
`permissions` — явно и по минимуму · никакого `pull_request_target`

# Подписка или API — в CI это разные секреты

| Оплата | Секрет | Откуда |
|--------|--------|--------|
| Подписка (Pro/Max) | `CLAUDE_CODE_OAUTH_TOKEN` | `claude setup-token` |
| API | `ANTHROPIC_API_KEY` | консоль Anthropic |

> ⚠️ **Обе сразу задавать нельзя.** При наличии `ANTHROPIC_API_KEY`
> приоритет у него — подписка молча не используется.

Прогоны по подписке расходуют **её лимит** и конкурируют
с вашей интерактивной работой

→ регулярное ревью на каждый PR: предсказуемее отдельный API-ключ
→ учебный проект и разовые прогоны: подписки достаточно

# Проверяет не тот, кто писал

Три субагента параллельно по всему проекту:

- **code-reviewer** — код Laravel, корректность в worker-режиме, тесты
- **security-auditor** — контейнеры, чарт, GitHub Actions, секреты
- **db-reviewer** — схема, миграции, индексы

→ сводный отчёт → исправления отдельными коммитами

**README пишет субагент со свежим контекстом**,
а не сессия, утомлённая длинной постройкой

---

# Публикация: когда что коммитится

| Момент | Git | Actions |
|--------|-----|---------|
| Конфигурация и границы | коммиты + **первый push** (через `ask`) | нечему бежать |
| Постройка под `/goal` | ветка `build/shop`, локальные коммиты | **не бегут** — push остановил бы цикл |
| Сейчас, после ревью | push ветки + **pull request** через MCP | **запускаются впервые**: тесты + ревью-агент |
| Блок 11 | merge | показ зелёного конвейера |

> Actions, включённые в самом начале, просыпаются только сейчас —
> workflow срабатывает на события, а не на факт настройки

# ADR: решение, а не декларация

Формат: **контекст → варианты → решение → последствия**

1. Отказ от php-fpm в пользу Octane: что даёт, чем оплачивается
2. FrankenPHP для каталога, RoadRunner для заказов — сравнение моделей
3. Разделение на два сервиса и способ взаимодействия
4. PostgreSQL и стратегия миграций

**Раздел «последствия» — честно:** ограничения worker-режима,
риск утечек памяти, `octane:reload` после деплоя

---

# Два рантайма — предмет сравнения

| | FrankenPHP | RoadRunner |
|---|---|---|
| Модель | PHP внутри сервера (Caddy) | Go-сервер + пул PHP-воркеров |
| IPC | нет | goridge |
| Из коробки | TLS, HTTP/2, HTTP/3, статика | плагины: Jobs, gRPC, KV |
| Ближе к | «всё в одном контейнере» | классике за обратным прокси |

Общее: приложение живёт между запросами → дисциплина в работе с состоянием

*Разные рантаймы в одном проекте — учебное решение ради сравнения*

# Схема — на Mermaid

GitHub рендерит нативно, отдельные инструменты не нужны

- схема компонентов стенда: сервисы, PostgreSQL, Redis, потоки запросов
- схема развёртывания в Kubernetes: образы, ingress, secrets, пробы

Документация и архитектурные решения — **часть результата**,
а не приложение к нему
